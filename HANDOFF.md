# Stratus Hub — передача проекта для разработки бекенда

Этот архив содержит исходный код, дизайн в виде работающего React-интерфейса, изображения, API-заготовку, общие библиотеки и конфигурацию Replit. Он **не** содержит базу данных с данными, секреты или установленные зависимости.

## Структура

- `artifacts/stratus-hub/` — сайт, личный кабинет, документация и все используемые публичные изображения (`public/images/`).
- `artifacts/api-server/` — Express API; на момент передачи реализован только `GET /api/healthz` (внутри роутера — `/healthz`).
- `artifacts/mockup-sandbox/` — отдельные рабочие дизайн-макеты на canvas; основное приложение находится в `stratus-hub`.
- `lib/api-spec/openapi.yaml` — контракт API; сейчас описана только проверка доступности.
- `lib/api-client-react/`, `lib/api-zod/` — сгенерированный клиент и схемы валидации.
- `lib/db/` — подключение PostgreSQL/Drizzle; таблицы пока не определены.
- `docs/` — материалы планирования; их содержание не следует считать реализованной функциональностью.
- `attached_assets/` — исходные референсы и вложения проекта.

## Как запустить

Требуются Node.js 24, pnpm и PostgreSQL для работы с базой. Из корня проекта:

```sh
pnpm install --frozen-lockfile
PORT=24619 BASE_PATH=/ pnpm --filter @workspace/stratus-hub run dev
```

Сайт будет доступен по адресу `http://localhost:24619/`. API запускается отдельно, с настроенной переменной `DATABASE_URL` (строка подключения к вашей PostgreSQL) и выделенным `PORT`:

```sh
DATABASE_URL='...' PORT=5000 pnpm --filter @workspace/api-server run dev
```

Для проверки кода: `pnpm run typecheck`; для сборки сайта: `PORT=24619 BASE_PATH=/ pnpm --filter @workspace/stratus-hub run build`.

На Replit настройки маршрутизации артефактов находятся в `artifacts/*/.replit-artifact/artifact.toml`. За пределами Replit нужно отдельно настроить проксирование `/api` к API-серверу.

## Что предстоит реализовать

Интерфейс кабинета, каталог цен, журналы, балансы, ключи, графики и примеры интеграции сейчас содержат демонстрационные данные и не являются подтверждением работающего API. Не использовать показанные цифры и тестовые ключи как реальные биллинговые данные. При реализации бекенда понадобятся договорённости о контрактах API, учётных записях и доступах, хранении и защите ключей, тарифах, фактическом учёте токенов и расходов, а также таблицы и миграции БД. Сначала обновляйте `lib/api-spec/openapi.yaml`, затем регенерируйте клиент командой `pnpm --filter @workspace/api-spec run codegen`.

**Секреты:** архив намеренно не содержит `.env`, токенов или дампа базы. Передавайте доступы отдельно через менеджер секретов, а не внутри ZIP. Не пересылайте в переписке приватные ключи или строку подключения к БД.
